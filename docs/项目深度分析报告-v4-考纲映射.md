## 〇、一页结论：v3 → v4 变了什么

三件事：

1. **教材核对发现一处硬错配**：计划 P4 写的「hello-agents 第 12 章」实际是《智能体性能评估》（核心指标、基准测试、评估框架），**不是** vLLM 部署。这意味着两件事同时成立——vLLM 需要外部资料（教材零支撑），而 ch12 的评估内容恰好是计划里漏掉的「评测」缺口。**把 ch12 读回来，评测缺口就地补上。**
2. **项目侧新增一整块素材：合规与分发**。首启版本化同意页 + 正式签名 + R8 + 凭据审计，不属于任何考纲条目，但它是「LLM 应用工程化」叙事的最后一块拼图——API Key 安全、数据边界、发布审计从此有代码级证据。
3. **剩余硬缺口与 v3 完全一致**（向量检索、真机、Reflection 完整版、MCP/A2A/Skill 八股、vLLM 另开项目），优先级未变。

## 三、计划文档本身的四个问题与修法

1. **P4 教材错配**（见上）。修法：P4 材料改写为「ch12（评估）+ 外部 vLLM 资料（官方文档 + 量化八股）」。
2. **「评测」在计划里没有名字**。LLM 应用岗现在必考：RAG 评什么（忠实度/答案相关性/上下文召回，RAGAS 类）、Agent 评什么（任务成功率/轨迹效率/pass^k）、线上怎么评（A/B、回归集）。教材 ch12 正好覆盖——从「第 12 章 = vLLM」的误会里解放出来，排进 P4 第一位，或提前到 P2 末。
3. **STAR 仍集中在最后一周**。v3 已产出 30 秒/2 分钟话术（好底子），但项目话术应该**每周往里挂新证据**：P1 学解码策略就挂「temperature 分层」，P2 学 Reflection 就挂「我为什么只做轻量版」。最后一周只做收口和模拟，不要那时才发现故事缺证据。
4. **题库不用外找**。Extra01（题目 + 参考答案）就在教材仓库里；「大模型工程面试题」若另有所指再单独核对。

## 五、STAR 30 秒版 v4（增量更新）

> HomeHealth 是本地优先的 Android 家庭健康管家。拍照上传体检报告后，Vision 大模型以 JSON 模式抽取 49 类健康指标，经 Schema 归一化层再人工确认入库。问答链路是双路径：指向具体指标的问题走 BM25 检索 + 引用溯源，泛化问题交给一个手写的 ReAct Agent——4 个只读健康数据工具，最多 5 轮，带完整护栏与降级。回答走 SSE 流式，每个数字都能追溯到具体记录。接 7 家供应商、双协议（含 Anthropic Messages 原生工具调用），每次调用都有本地可观测日志。**首启有版本化的隐私与免责同意，正式签名发布，发布包经 13 类凭据审计零命中——健康数据只去用户自己配 Key 的模型厂商。**

新增追问预案：

- 首启同意为什么做版本化？（文案有实质变更时老用户必须重看——合规不是一次性弹窗）
- 权限为什么在同意之后才申请？（同意前置 = 有意义的同意）
- 发布包怎么证明没有泄漏？（审计脚本 13 类 + sha256 + 签名指纹公开可核）
- R8 混淆对 Gson 反序列化有什么风险？（字段名混淆 → keep 规则；这正是真机回归清单第一项）
