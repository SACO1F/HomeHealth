## 1. What it is

HomeHealth (家庭健康管家) is a **local-first, privacy-focused Android family health manager**. Snap a photo of a lab report → a Vision LLM extracts structured metrics in JSON mode → a normalization layer standardizes names/units → the user confirms → records land in an on-device Room DB. On top of that: trend charts, three-rule anomaly detection, a bilingual UI, medication reminders, and a health Q&A feature that routes between keyword retrieval and a hand-written ReAct agent.

It is a **solo-built, portfolio/interview-grade project** — the `docs/` folder also contains interview-prep material (Agent-role interview guides, a 100-question bank, syllabus mapping), which frames many of the deliberate engineering decisions.

## 3. Architecture

```
Presentation  →  ui/ (Compose screens, ViewModels, navigation, theme)   [8 screens]
Domain        →  domain/ (models, repository interfaces, use cases, agent tools)
Data          →  data/ (Room entities+DAOs, remote LlmClient, repository impls)
Cross-cutting →  di/ (Hilt), worker/ (WorkManager+Alarm), util/ (SchemaNormalizer, HealthTypes…)
```

- **DI**: Hilt throughout — `DatabaseModule` (DB + 9 migrations + 7 DAOs), `NetworkModule` (OkHttp/Gson), `RepositoryModule` (interface→impl bindings).
- **Navigation**: single `MainActivity` + `NavGraph`, 8 screens (family list, member detail, record detail, document upload, QA, alerts, reminders, settings) + a versioned first-run `ConsentScreen` and a `SplashActivity`.
- **State**: `StateFlow` + `collectAsStateWithLifecycle`; ViewModels hold an `internal MutableStateFlow` merged with repository flows.

## 4. Core pipelines

### 4.1 Report parsing (non-streaming, deliberate)
`Photo → saveImageAndCreateDocument (UUID filename) → compress to base64 → Vision LLM (JSON mode, temp 0.1, maxTokens 4096) → parseRecordsJson (brace-balanced JSON extraction, tolerates ```json fences) → SchemaNormalizer.normalize per record → editable cards → confirmRecords`.
- `confirmRecords` is wrapped in `database.withTransaction { deleteBySourceDocument + insertAll + update(COMPLETED) }` — this closes a previously-identified duplicate-import hole.
- `rawText` + `normalizationNotesJson` are now persisted (DB v9), enabling audit/replay.
- Stuck `PROCESSING` documents are reset to `FAILED` with **rate-limiting + in-flight skip**.
- `DocumentUploadViewModel.parseInternal` catches `Throwable` (incl. `OutOfMemoryError`) → retryable error state.

### 4.2 Health Q&A (streaming, two paths + fallback)
Routing in `QARepositoryImpl.askStream`:
1. **Fast path** — question contains a *strong metric term* (`QaRetriever.strongTermsOf`) → BM25 Top-12 retrieval over the member's records → SSE stream, `[n]` citation enforced.
2. **Agent path** — no strong term but there is data/image → hand-written ReAct loop (`ReActAgent`, ≤5 turns, ≤8 tool calls) over 4 read-only tools (`search_records`, `get_reference_range`, `get_alerts`, `read_report_image`).
3. **Offline fallback** — no key / no records / failure → `LocalQaEngine` rule engine.

Design details that matter: the "data basis" block is emitted *before* the first token (local, always available); retrieval-path citations map `[n]` to records; agent answers are committed in one piece (not token-streamed) because only at turn-end is it known to be final; the last agent turn drops tool declarations so "budget exhausted" and "normal finish" share one path.

### 4.3 Anomaly detection (three rules)
`DetectAnomaliesUseCase`: **(1) out-of-range** (sex-specific ranges; conservative comparator handling — `<0.1` only alerts when the boundary itself crosses); **(2) trend** (3 same-direction readings, cumulative change ≥ per-metric threshold, within a 180-day window); **(3) personal baseline** (current vs median of ≥5 own samples). De-dup = 7-day window + severity escalation. Unit gate: records whose normalized unit ≠ the dictionary unit are skipped (no cross-unit false alarms). Interval-valued records are excluded from trend/baseline. Alerts are stored **structurally** (`metricType`/`direction`/`valueText`/`refText`/`spanText`) + Chinese text fallback, and rendered per current locale at display time.

### 4.4 Medication reminders
Now genuinely time-based: `MedicationAlarmScheduler` uses `AlarmManager.setExactAndAllowWhileIdle` (falling back to inexact without permission), one alarm per (reminder, time), rescheduled by `MedicationAlarmReceiver` on fire and on boot/timezone/time-set/package-replaced. Calendar export writes daily events with a 5-min alert and a stable `[homehealth:med:<id>]` marker for idempotent cleanup; edits/toggles/deletes reconcile calendar events with orphan protection.

## 5. Data model & migrations

7 entities: `family_members`, `health_records`, `medical_documents`, `alerts`, `medication_reminders`, `qa_history`, `llm_call_logs`.

- **Migrations v1→v10** are all hand-written; **`fallbackToDestructiveMigration()` is deliberately absent** — a version jump fails loudly rather than wiping health data.
- Migration SQL for v4→v10 is centralized in `AppMigrationSql` and **shared with JVM tests** so the DDL can't silently drift from the committed schemas (`app/schemas/…/4.json`…`10.json`).
- Notable modeling: `health_records.comparator` (LT/GT for `<0.1` / `>100`); `alerts` 7 structured columns; `qa_history.imagePath`; `medical_documents.rawText` + `normalizationNotesJson`; `family_members` 8 health-profile columns (v10).
- `@Upsert` is used instead of `INSERT OR REPLACE` to avoid SQLite REPLACE's delete-then-insert firing FK cascade deletion.

## 6. LLM integration layer

- **Dual protocol**: OpenAI-compatible `chat/completions` and native **Anthropic Messages API** (system param split, base64 image `source`, `anthropic-version` header, temperature-1 fallback for extended thinking).
- **Asymmetric streaming**: Q&A streams (SSE); report parsing stays single-shot (needs the complete JSON).
- **Retry policy**: exponential backoff + jitter, restricted to 429 / 5xx / IO; streaming retries only *before* the first delta (a retry after partial output would duplicate text).
- **Cancellation**: non-streaming (`executeCancellable`) and streaming both cancel the in-flight OkHttp `Call` on coroutine cancellation.
- **Strict vision/text separation**: parsing requires a vision model; a text model is rejected at runtime with an actionable message. Attached images resolve a vision route (QA provider → parse-service fallback) and the source is disclosed in the answer.
- **Observability**: every call logs provider/model/scene/latency/prompt&completion chars/attempts/failure-type to `llm_call_logs` — **never prompts or responses** (those contain health data).
- **Agent gateway**: `ReActAgent` uses the text model; images reach the vision model only through the `read_report_image` tool (the user turn carries no inline image), matching the documented design.

## 7. Privacy & security

- `android:allowBackup="false"` — closes `adb backup` / cloud-backup extraction.
- API keys encrypted with **Android Keystore AES-256-GCM** (random IV per encryption, key material never leaves the TEE); legacy plaintext keys are migrated in place; unreadable keys are surfaced as a distinct state instead of "not set".
- **Versioned first-run consent** (`CONSENT_VERSION_CURRENT`) gating the entire UI and permission requests.
- FileProvider is not exported; image writes are path-validated; ProGuard/R8 keep rules cover Gson DTOs, Room entities, Hilt, WorkManager.
- Data leaves the device only on explicit user action, going **directly to the user's own configured provider** with the user's own key.

## 9. Strengths

1. **Coherent, mature architecture** — clean layering, Hilt, single-source-of-truth migration SQL, deliberate absence of destructive migration.
2. **Genuinely thoughtful LLM engineering** — dual protocol, asymmetric streaming, cancellation, scoped retry, and observability that avoids copying sensitive data.
3. **Defensible privacy posture** — two independent layers (backup disabled + Keystore encryption), versioned consent, no developer server.
4. **Consistency of the normalization + detection story** — alias/unit/conversion dictionaries shared across retrieval, QA context, and detection; conservative interval handling.
5. **Outstanding inline documentation** — nearly every non-obvious decision carries a "why" comment (the codebase reads as an engineering rationale, not just an implementation).
6. **Complete bilingual product surface** — 381/381 string-key parity, including notifications and calendar events.

## 10. Current gaps, risks & recommendations (prioritized)

**P1 — worth fixing soon**
1. **Doc/code drift (see §11).** The README and some docstrings describe DB v9; the code is v10. Update the migration table and version references.
2. **Agent "evidence == what the model saw" is not strictly true.** `ReActAgent` appends the *full* tool text to `evidence` while the model receives the truncated observation (`OBSERVATION_CHAR_BUDGET = 1500`). When truncation fires, the user's "data basis" block can contain more than the model saw, contradicting the `buildAgentReferences` docstring. Truncate evidence the same way (or annotate it).
3. **Notification-permission re-prompt on rotation.** `MainActivity.RequestNotificationPermissionOnce` uses `remember` (not `rememberSaveable`) for its `requested` flag.

**P2 — polish**
4. **Daily worker drift.** The 24h `PeriodicWorkRequest` with a one-shot initial delay will drift after DST/timezone changes; consider rescheduling on `TIMEZONE_CHANGED`.
5. **Consent ordering edge.** `HomeHealthApp.onCreate` schedules the daily health-check worker unconditionally — before consent is verified. On a fresh install or a consent-version bump, a health-alert notification could theoretically precede consent.
6. **`HealthTypes.labelRes` still returns `0` for unknown types.** All current call sites funnel through the safe `metricLabel()` helper, but the raw function remains a latent crash footgun for any new call site.
7. **Camera temp filename uses `System.currentTimeMillis()`** (`DocumentUploadViewModel.prepareCameraCapture`); the persisted copy uses UUID, but the temp path could collide within the same millisecond.
8. **Test coverage gap** for networking, repositories, and UI — the highest-value additions would be `LlmClient` stream/retry tests and a few ViewModel tests.

**Roadmap (self-acknowledged in README)**
9. No vector/hybrid retrieval (BM25 only) — the single largest RAG gap.
10. No MCP server exposing health tools; no on-device LLM; no Health Connect integration.
11. Reference ranges lack cited sources and age/pregnancy stratification (documented TODO in `HealthTypes`).

**Cosmetic**
12. `applicationId` (`com.adajunk.homehealth`) ≠ `namespace` (`com.example.homehealth`); the `com.example` namespace is a placeholder-style name.

  - Calendar orphan events on reminder edit → fixed with new-then-delete + marker-based cleanup.
  - Non-streaming LLM path without cancellation → fixed via `executeCancellable`.
  - `rawText` / `normalizationNote` not persisted → fixed (v9 columns).
  - `unreadableKeys` non-thread-safe → fixed (`ConcurrentHashMap.newKeySet`).
  - Notification/calendar hardcoded Chinese → fixed (string resources; legacy Chinese literals kept only for back-compat cleanup).
- **The 2026-09-23 bug doc and v4 syllabus-mapping report** should be treated as historical; this report supersedes their project-state conclusions.

## 12. Overall verdict

HomeHealth is a **well-architected, unusually well-documented Android application** whose engineering quality is well above typical solo/side-project level. Its differentiators are real and implemented, not aspirational: local-first privacy with two independent defenses, a normalization layer that prevents cross-unit false alarms, a conservative three-rule anomaly engine, a two-path Q&A design that deliberately keeps the fast path instead of "agent-washing" everything, and LLM observability that avoids duplicating sensitive data.

The remaining work is mostly **maintenance and depth**, not correctness: sync the docs with the v10 schema, tighten a few small edges (evidence truncation parity, consent ordering, permission-flag persistence), broaden test coverage beyond pure logic, and (per the project's own roadmap) add vector/hybrid retrieval to complete the RAG story.
