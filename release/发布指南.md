## 二、🔴 上架前必须解决的阻塞项

以下三项如不处理，国内主流商店**会直接驳回**。

### 阻塞项 1：包名已改为 `com.adajunk.homehealth`（2026-09-16 已处理）

```
原: applicationId = "com.example.homehealth"   ← com.example.* 全商店拒绝
现: applicationId = "com.adajunk.homehealth"   ← 已改并重新打包
```

⚠️ **重要区分**：`namespace` 仍保持 `com.example.homehealth`，这是**故意的**。
- `namespace` 决定代码里 `R` 类与类的全限定名路径，**改动会导致全部源码 import 失效**，且与商店无关。
- `applicationId` 才是商店识别应用的唯一标识，**上架后永久不可改**。

两者可以不同，这是 Android 官方支持的正常做法。当前状态无需再动。

> 若日后想统一命名空间，需在 Android Studio 里做 Refactor → Rename Package 全量重构，
> 属于纯代码整洁性改动，**建议不要在临近上架时做**。

### 阻塞项 3：缺少商店要求的合规材料（非技术项）

国内商店普遍要求，请提前准备：

| 材料 | 说明 |
|---|---|
| **软件著作权证书** | 国内商店**几乎强制**，办理周期约 1–2 个月（加急约 1 周）。**建议立刻启动** |
| **开发者实名认证** | 各商店开发者账号均需实名，企业认证比个人认证权限更大 |
| **隐私政策 URL** | 必须提供可公网访问的链接，内容需与 App 实际行为一致 |
| **App 备案** | 2023 年 9 月起工信部要求，需通过云服务商或应用商店完成 ICP/App 备案 |

**⚠️ 隐私政策特别提示**：你的 App 会把**体检报告图片与健康指标**发送给第三方 LLM 供应商
（智谱/通义/DeepSeek 等）。这属于「向第三方共享个人信息」，**隐私政策里必须明确披露**：
- 具体共享哪些字段（图片、指标名、数值）
- 接收方有哪些（列出所有内置供应商）
- 用户如何关闭（在设置页禁用 LLM 即可，需在政策中说明）

README 中「健康数据不上传任何第三方服务器」的表述**与实际情况存在出入**——
健康数据确实不上传**你们的服务器**（端侧直连），但会发送到用户配置的 LLM 厂商。
这句话在商店审核时可能被判定为**虚假宣传**，建议措辞改为
「不经过第三方中转服务器，数据仅直连用户自行配置的 LLM 服务商」。

### 版本号规则

每次提交商店前**必须递增** `app/build.gradle.kts` 中的：

```kotlin
versionCode = 2          // 整数，每次发布必须 +1，商店据此判断新版本
versionName = "1.2.0"    // 展示给用户，语义化版本
```

`versionCode` 重复会导致上传被拒。
